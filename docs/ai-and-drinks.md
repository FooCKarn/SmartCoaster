# ตรวจจับการดื่ม + AI ยกป้าย + LINE อัตโนมัติ

ทุกอย่างอยู่บน **gateway** (node แค่ส่งน้ำหนักกับระยะมาเหมือนเดิม)

```
node ──น้ำหนัก/ระยะ──▶ gateway ─┬─ DrinkDetector ──ดื่ม──▶ /drinks (Firebase) + ป้ายลง
                                │
DHT11, KY-038, PIR ────────────▶├─ AI (logistic regression) ──ความเสี่ยง p──▶ ยก/ลดป้าย (servo)
                                │                                    │
                                └─ ป้ายยกค้าง ≥ 10 นาที ยังไม่ดื่ม ──▶ LINE broadcast
```

## 1. ตรวจจับการดื่ม (`gateway/drink_detect.h`)

- จำ "น้ำหนักตอนนิ่ง" ของแก้วไว้ (นิ่ง = ค่าห่างกันไม่เกิน 5 g สองคู่ติดกัน ≈ 10 วินาที)
- น้ำหนักนิ่งใหม่ **ลดลง ≥ 15 g** → ดื่มไป (น้ำ 1 g ≈ 1 ml) บันทึกที่ `/drinks`
- **เพิ่มขึ้น ≥ 30 g** → เติมน้ำ บันทึกที่ `/refills`
- ยกแก้วขึ้น (น้ำหนัก < 40 g) ยังไม่นับ รอวางกลับแล้วนิ่งก่อนค่อยเทียบ
- จิบเล็ก ๆ < 15 g จะถูกสะสมจนถึงเกณฑ์แล้วนับรวมทีเดียว
- ค่าเกณฑ์ทั้งหมดแก้ได้ใน `struct DrinkConfig`

## 2. AI ตัดสินใจยกป้าย (`gateway/ai_model.h`, `ai/train.py`)

**โมเดล:** logistic regression ทำนายว่า "60 นาทีข้างหน้าผู้ใช้จะดื่มน้ำไม่พอ" (ความเสี่ยง p = 0..1)

| feature | มาจาก |
|---|---|
| `mins_since_drink` นาทีตั้งแต่ดื่มครั้งล่าสุด | load cell (node) |
| `ml_last_hour` ดื่มไปเท่าไรใน 1 ชม. | load cell |
| `ml_today` ยอดวันนี้ (รีเซ็ตเที่ยงคืนตามเวลา NTP) | load cell |
| `room_t`, `room_rh` | DHT11 |
| `present` มีคนนั่งอยู่ | PIR ขยับภายใน 5 นาที หรือ ultrasonic < 80 cm |
| `sound_p2p` ห้องเสียงดัง (ยุ่ง/โฟกัส มักลืมดื่ม) | KY-038 |

**ตัดสินใจ (closed loop):** p ≥ 0.60 → ยกป้าย · p ≤ 0.52 → ลดป้าย · ดื่มแล้ว → ป้ายลงทันทีและค้างไว้ 15 นาที
**LINE:** ป้ายยกค้าง ≥ 10 นาทีแล้วยังไม่ดื่ม → broadcast (ห่างกันอย่างน้อย 30 นาที กันโควตาหมด)

### เทรนโมเดลใหม่ด้วยข้อมูลจริง (ทำก่อน final)

ตอนนี้ `ai_model.h` เทรนจาก **ข้อมูลจำลอง** 60 วัน (`python ai/train.py --synthetic`) เพื่อให้ระบบทำงานได้ก่อน
gateway เก็บ feature (`ai_x`) ไว้ในทุก reading และเก็บการดื่มใน `/drinks` อยู่แล้ว เปิดทิ้งไว้หลายวันแล้ว:

1. `pip install numpy`
2. Firebase console → Realtime Database → ⋮ → **Export JSON**
3. `python ai/train.py --firebase <ไฟล์ที่ export>` (ข้อมูลยังน้อยให้เติม `--mix-synthetic`)
4. สคริปต์พิมพ์ accuracy / precision / recall / F1 เทียบกับกฎธรรมดา "ไม่ดื่ม > 45 นาที" → ใส่ใน report หัวข้อ AI accuracy ได้
5. อัปโหลด gateway ใหม่ (ไฟล์ `gateway/ai_model.h` ถูกเขียนทับแล้ว)

> ข้อมูลที่ติด `demo: true` (ตอนเปิดเร่งเวลา) จะไม่ถูกเอาไปเทรน

## 3. ถ่ายวิดีโอ: โหมดเร่งเวลา

ตั้ง `#define DEMO_SPEED 60` บนสุดของ `gateway/gateway.ino` (หรือ `-DDEMO_SPEED=60` ใน PlatformIO)
แล้ว 1 วินาทีจริง = 1 นาทีในระบบ:

1. วางแก้ว รอ ~2 นาที ไม่ดื่ม → Serial `[SIGN] UP` ป้ายยก
2. รออีก ~10 วินาที → LINE เด้งบนมือถือ
3. ยกแก้วดื่ม วางกลับ → `[DRINK] drink 40 g` ป้ายลง, dashboard ยอดวันนี้เพิ่ม

**ถ่ายเสร็จแล้วเปลี่ยนกลับเป็น `1`** ไม่งั้นข้อมูลที่เก็บไปเทรนจะใช้ไม่ได้

## 4. คำสั่ง Serial ของ gateway (115200)

| พิมพ์ | ผล |
|---|---|
| `a` | คำนวณ AI ทันทีแล้วพิมพ์ค่า feature + p |
| `u` / `n` | ยก / ลดป้ายเอง (ทดสอบเซอร์โว) |
| `c` | ปลดหยุดฉุกเฉินหลังกดปุ่ม e-stop |
| `m` | ส่ง LINE ทดสอบทันที (ใช้โควตาจริง) |
| `q` | ดูโควตา LINE ที่ใช้เดือนนี้ |
